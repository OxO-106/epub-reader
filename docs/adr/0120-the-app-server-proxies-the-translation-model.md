# The app server proxies the translation model; the browser never talks to it

Live translation goes browser, then the app's own `/api/translate`, then the model server (`READER_TRANSLATE_URL`), never browser straight to model. The alternative, pointing the page at the model server's address, would be simpler code, but it needs the model server reachable from every device (a phone on Tailscale cannot reach `127.0.0.1`), a CORS and Content-Security-Policy hole (`connect-src` is `'self'` on purpose, since Books are untrusted content), and the API key in the page. Going through the app server keeps one address for every device, lets the server hold the key, cap concurrent requests to a single-slot laptop model, queue the rest in order and abort upstream work when a browser leaves, and gives one place that guarantees Book text is never logged or stored. The cost is one extra hop and a streaming protocol of our own (newline-delimited JSON) between page and app server.
