# The Chinese font is cut from the owner's installed copy into a git-ignored folder, and served from there

The Chinese typeface 京华老宋体 has no stated licence (its copyright line is "All rights reserved"), and this repository is public, so neither the font file nor any piece or derivative of it is ever committed. `npm run fonts:build` (`scripts/build-fonts.py`, Python with `fonttools` and `brotli`) reads the copy installed on the owner's PC and writes woff2 pieces with `unicode-range`, a style sheet and a manifest to `./fonts` (`READER_FONTS_DIR`), which `.gitignore` covers; the script also refuses an output folder that git would track. The server serves that folder read-only under `/fonts/` and reports at `GET /api/fonts` whether the font is there, and the front end declares the `@font-face` rules (in the page and in every Book document) only when it is. Without the font nothing breaks: the stacks fall through to system serif fonts, or to a copy installed on the device. We chose this over bundling the font (a licence we cannot show) and over a download step from the internet (nothing official to download, and the app must work offline).

The cost is that a fresh checkout has no Chinese font until the owner runs the script on a PC that has it installed, and that the tests cannot use the real 35 MB font: they use a tiny generated stand-in (`scripts/fixture-assets/make-standin-cjk-font.py`) in a temporary fonts folder, so a real `./fonts` folder never changes a test. The pieces are declared under the name "KingHwa Web", not the font's own names, and they leave out ASCII: a copy installed on a device (which has Latin glyphs) must not take over English text from Libertinus Serif, the bundled English face (OFL, see `THIRD-PARTY-NOTICES.md`).
