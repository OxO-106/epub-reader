# Render Markdown in the browser, sanitize it, and let it load web images

The server stores a Markdown Book as the original bytes and the browser renders it (markdown-it, then DOMPurify, then an adapter that presents the HTML sections to foliate-js as a Book), instead of the server converting it to HTML or an EPUB at import. We chose this so the stored file stays the author's file, rendering can improve without re-importing, and nothing new runs on the server. Markdown is untrusted input, so raw HTML in it is passed through DOMPurify before it reaches the Reader's same-origin iframes; the Content-Security-Policy from ADR 0005 stays as the second layer. The one deliberate loosening is `img-src`, which now allows `https:` and `http:` because notes link to pictures on the web; it is the only directive that changed, and it means opening such a Book makes your browser request those images, which tells the image's host that you opened it. If that matters more than seeing remote images, remove those two sources from `src/server/security.ts` and the images simply stop loading. Syntax highlighting uses highlight.js core with about twenty registered languages and no language guessing (a code block in any other language shows as plain code), chosen over Shiki and Prism for its size and because it needs no build step or WebAssembly.
