## Commands

Node 24+ and npm; TypeScript runs directly on Node (no compile step for the server). Run from the repo root.

- Install: `npm install`
- Start (build front end, then serve everything on http://127.0.0.1:5174): `npm start`
- Dev (API with auto-restart plus Vite hot reload, open http://localhost:5173): `npm run dev`
- Typecheck: `npm run typecheck`
- API tests (real server, real temp folders and SQLite, Vitest): `npm test`
- Browser tests (builds first, then headless Playwright; import `test`/`expect` from `tests/e2e/fixtures.ts`, which starts a fresh real server with throwaway folders per test, using installed Chrome, else Edge; set `READER_E2E_CHROME` to use another executable): `npm run test:e2e`
- Everything: `npm run test:all`
- Configuration: `READER_DATA_DIR` (default `./data`), `READER_LIBRARY_DIR` (default `./library`), `READER_PORT` (default 5174), `READER_HOST` (default `127.0.0.1`), `READER_FONTS_DIR` (default `./fonts`). Settings (`src/server/settings.ts`, `settings-routes.ts`): the Settings screen saves the library folder, network and translation settings to `settings.json` in the data folder; effective value = explicit `startServer` option > environment variable > saved > default (`resolveConfig(overrides, env, saved)`); translation settings apply live (the server swaps its translator), the rest on restart (optional `restart` hook). Writes go through `request-guards.ts`: own Origin, a Host that is an IP, localhost or `*.ts.net` (DNS rebinding), JSON, size limit. Tests pass `env: {}` to `startServer` to ignore the shell's variables.
- The library folder is watched (`src/server/library-folder.ts`): files present at startup and files added or changed later go through `importBook`; failures are listed at `GET /api/library-folder`. Timings are `librarySettleMs` and `libraryRescanMs` server options (tests shorten them).
- Translation (`src/server/translate*.ts`): `READER_TRANSLATE_URL` (unset = not set up), `READER_TRANSLATE_MODEL`, `READER_TRANSLATE_API_KEY`, `READER_TRANSLATE_CONCURRENCY` (default 1; the waiting line is capped by `maxQueue`, default 64, a translate option with no environment variable: one more gets 503 `busy`). `POST /api/translate` needs `Content-Type: application/json` (else 415), an `Origin` header if present naming the request's own host (else 403), and a body of at most 128 KiB (413). `READER_TRANSLATE_URL` may not contain credentials, and config errors never repeat its value. The app server proxies an OpenAI-style streaming model server (ADR 0120); the prompt and generation settings are isolated in `src/server/translate-prompt.ts`. Proper names are put into Chinese by their sound, not their meaning (ADR 0150, superseding the masking of ADR 0130): `translate-names.ts` finds them (stop-list in the data file `name-stop-list.txt`) and `translate-prompt.ts` lists them in the prompt with the transliteration rule; the text is sent unchanged and the answer is passed through as it is; `POST /api/translate` takes `{text, context?, names?, bookId?}`, where `names` (at most 500 strings of at most 80 characters) are names the caller already knows. With `bookId`, the Book's Glossary (ADR 0170; `glossary.ts`, table `glossary`, API `glossary-routes.ts` at `/api/books/:id/glossary`) fixes each name's Chinese form: new names get one short name request (`namesRequest` in `translate-prompt.ts`), checked by `chineseForm`/`parseNameForms` and saved (the first form saved wins; a reader-set form is never replaced); a failed name request falls back to the plain rule. The panel is `GlossaryPanel.tsx` (English Books; `Reader.retranslate()` after a change). The model stand-in answers name requests on its own (`names` option, `nameRequests()`), apart from `chatRequests()`. Never log or store the text being translated; names are stored only in a Book's Glossary, never logged.
- Model stand-in for tests: `tests/helpers/model-stand-in.ts` is a real HTTP server speaking the streaming chat-completions protocol with scripted replies (delays, errors, malformed streams) and a request log (including aborts). Use it from Vitest (`startModelStandIn()`, with `startTestServer({ translate: { url: model.url } })`; translation is off unless a test sets a URL) and from Playwright (`test.use({ withModel: true })` plus the `model` fixture, or `translateUrl`).
- Regenerate sample files in `tests/fixtures`: `npm run fixtures` (the Kindle fixtures are written by `scripts/kindle-writer.ts`, MOBI 6 and KF8, so no downloaded sample is needed). Kindle files: server-side header reader `src/server/formats/mobi.ts` (title, author, cover, DRM flag; `ProtectedBookError` gives the "protected" refusal); the Reader uses foliate-js's own `mobi.js`. PDFs: server `src/server/formats/pdf.ts` reads title and author, and draws the first page as the cover (`@napi-rs/canvas`, time- and size-limited, left out on any failure), with pdfjs-dist (pinned to 5.5.207, the build foliate-js's `pdf.js` expects; a password-locked PDF is refused as protected); the Reader opens them with foliate-js's `pdf.js` adapter, whose pdf.js files `vite.config.ts` (`pdfjsFromPackage`) serves from the package in dev and copies to `assets/vendor/pdfjs/` in the build. PDFs are fixed layout: `Reader.isFixedLayout()`, zoom instead of the text settings (`pdf-zoom.ts`), no translation, and their own search (`reader/pdf-search.ts`, through pdf.js's text extraction).
- Highlights (ADR 0160): table `highlights` in `db.ts` (deleted with the Book in `db.deleteBook`), routes in `src/server/highlights.ts` at `/api/books/:id/highlights` (GET list; PUT `/:highlightId` upserts with a client-made id, the newer `updatedAt` winning; DELETE), guarded like the settings writes; colours in `src/shared/highlight-colors.ts`, painted per theme from `themes[theme].highlights` at `highlightOpacity` (`tests/unit/highlight-colors.test.ts` keeps text 4.5:1 through them). The Reader draws them with foliate-js's overlayer (`setHighlights`), reports selections (`onSelection`, `byKeyboard` when Shift is released) and taps on them (`onHighlightTap`); the screen side is `src/web/highlights.ts` (`useHighlights`), `HighlightMenu.tsx` and `HighlightsPanel.tsx` (reading order and chapters from `Reader.placeHighlights`; notes; Markdown export in `highlights-export.ts`). Not for fixed-layout Books.
- Text size (`src/web/reader/font-scale.ts`): when a reflowable Book page loads, every element's size is read as if the base were the browser's 16 px and written back as the same multiple in `rem` (inline, `!important`), so sizes a Book sets with keywords, px, pt or inline styles follow the Display setting (`html { font-size }`) and keep their proportions; only `style` attributes change, so CFIs are unaffected. `tests/e2e/font-size.spec.ts` with `tests/fixtures/sizes.epub` covers it. IBM Plex Sans is the interface font and a Display font choice (`plex`, shown as "Plex"), bundled from `@fontsource/ibm-plex-sans` next to Libertinus (`src/web/fonts.ts`; notices in `THIRD-PARTY-NOTICES.md`).
- Fonts (ADR 0100): English is Libertinus Serif from the npm package `@fontsource/libertinus-serif`, bundled (notice in `THIRD-PARTY-NOTICES.md`). The Chinese font 京华老宋体's original is committed at `assets/fonts/KingHwa_OldSong-2.002.ttf` (ADR 0140, which supersedes the "never committed" part of ADR 0100); its web pieces are generated, not committed: `npm run fonts:build` (`scripts/build-fonts.py`; needs `pip install fonttools brotli`; takes minutes) cuts the repository's copy (else the one installed on this PC) into the git-ignored `./fonts` (`READER_FONTS_DIR`), which the server serves read-only at `/fonts/` and reports at `GET /api/fonts`. The front end declares it under the family name "KingHwa Web" only when present (`src/web/fonts.ts`), in the page and in every Book document through `Reader.setFontFaces` and `bookStyles`. Tests never use the real font: `startTestServer` and `tests/e2e/fixtures.ts` give each server an empty fonts folder inside its temp folder, and `test.use({ standInFont: true })` / `writeStandInFonts` (`tests/support/stand-in-font.ts`) fills it with the tiny generated stand-in (`scripts/fixture-assets/make-standin-cjk-font.py`).
- Design tokens (colours per theme: light, sepia, dark, black; fonts, radii) are CSS custom properties in `src/web/theme.css`; the Book's palette and serif stacks in `src/web/display-settings.ts` must stay in step with them (`tests/e2e/theme.spec.ts` checks the colours). The design is the Claude Design canvas in `.scratch/reader-redesign-2/spec.md`. The Reader's bars rest (fade to a running head and foot) while reading: `data-chrome` on `.reader-screen`, driven by `ReaderScreen.tsx` from `Reader.onTap`, page turns, pointer and focus; nothing may depend on `:hover` (`expectNoHoverOnlyContent`).
- One-click start (Windows): `Start Reader.cmd` runs `scripts/reader-tray.ps1`, which starts `npm start` and llama-server hidden and keeps a system-tray icon (two dots: Reader, Translation; green running, amber starting, red stopped, grey not set up). `Stop Reader.cmd` (`reader-tray.ps1 -Stop`) quits it and stops what it started; servers it found already running are left alone. Logs and `status.json` are in `%LOCALAPPDATA%\Reader`. It is a desktop utility without automated tests: check it by running it (the status file shows the states) and stop it afterwards.
- Translation model server (Windows; llama.cpp and the model are never committed: they live in the git-ignored `translation-models/` in the repo, which the scripts prefer when the model is there, or in `%USERPROFILE%\translation-models`; see `docs/translation-setup.md`): `npm run translate:server`, then start the app with `READER_TRANSLATE_URL=http://127.0.0.1:8080`.

Layout: `src/server` (Hono API, `node:sqlite`), `src/web` (Preact app; `src/web/reader/translation` is the live-translation engine, plain DOM with no foliate-js, driven through the Reader interface), `tests/api`, `tests/unit`, `tests/e2e`, `tests/fixtures`. Browser tests switch translation on and off with the real Translate button (`setTranslation` in `tests/e2e/translation-helpers.ts`) and read or move the Reader through `window.__reader`, a seam the Reader screen offers for tests (status, `goTo`, `next`, `onLocation`, `retryTranslation`). The bilingual style is in `src/web/reader/translation/style.ts`; its colours are the `themes` palette in `display-settings.ts` and the `--gloss-*` and `--alert-soft` tokens in `theme.css`, which a unit test keeps equal. Use `.ts` extensions in relative imports. foliate-js is vendored in `src/web/vendor/foliate-js` and only `src/web/reader/reader.ts` may import it at runtime (type-only imports of the vendored typings are allowed elsewhere; ADR 0005); the server's Content-Security-Policy is in `src/server/security.ts`.
